# 世界书分段规划

> **状态：图纸 v3（2026-11-09 第二次修）**
> v2 砍过头了 —— 见第一节。本文决定条目怎么分段、多长、常驻还是关键词触发。

---

## 一、先纠一次偏

v2 我按"跟人无关就砍"的逻辑砍了 13 条，砍错了。

**天材地宝、剿匪、三榜、经济、势力演变、奇遇、NPC 境界同步、随机生成 —— 这些不是冗余，是开放世界的探索动力。** 全砍掉，大世界就只剩一张布景，成长也没有可捞的东西，两条腿一起瘸。

真正该砍的是另一类东西：

| 该砍的 | 例子 | 为什么 |
|---|---|---|
| **纯精算细节** | 战力推演的 CR 手算公式、逐档系数表、群战拆回合 | 武侠不该像跑团；这些由脚本或一句规则解决，不该占 1.2 万字 |
| **无出口系统** | 百艺（琴棋书画锻造炼丹）、驯兽 | 设计了但没有玩法出口，属于"作者想有"而不是"玩家要用" |
| **重复表达** | 三榜 + 声望 + 绰号 都在讲名声 | 合并，不删 |
| **过长的单条** | 好感度 5094 字、群战 7198 字 | 一条规则只该讲一件事 |

大凉的病不是"系统多"，是**每条都太长、彼此还重叠**。所以这一版的原则改成：

> **条目数不减，单条砍到 1/3。**

## 二、三条腿，怎么平衡

| | 大凉 | 刀剑遣流年 |
|---|---|---|
| 世界探索 | 主角 | 主角之一 |
| 成长 | 重要 | 主角之一 |
| **人与人的情感** | 一条 5094 字兜着 | **与另两条同权，且有自己的机制** |

注意一件事：**天材地宝、秘境、奇遇、秘境掉落，这四样同时喂两条腿**——既是"世界可探索"，也是"成长的资源来源"。v2 把它们归到"跟人无关"里砍掉，等于一次砍两条腿。

所以分类不能非此即彼。真正只服务"人"的是人物条目，真正只服务"世界运转"的是势力与动态，中间一大片是共用的。

### 定案：百艺与驯兽 → 甲案

合并成一条 **「杂学」**，800 字，只写气质与场合，不做等级与产出。已落 `Source/Rules/杂学.txt`。

所以 H 段实为 **19 条**。

### 条目源在哪

条目正文写在 `Source/Rules/*.txt`（一条一文件，纯文本，方便你直接改）。
打包阶段由脚本读 `Source/Rules/` 生成世界书条目，不手抄第二份。

**注意**：`Source/` 因此不再是只读素材区，而是"正文源区"。`Source/World Lore/` 仍是你的手写 lore，工具链不覆盖。

## 六、单条为什么必须短

大凉最长的一条是"剧情线叶调度"102,379 字。第二长是"战争？"不，是群战 7,198、战力推演 7,412、好感 5,094。

一条规则超过 2500 字，模型就开始挑着看——它会读完前三分之一，然后假装后面不存在。这不是猜测，是长条目在上下文里的典型失效方式。

所以硬度规则：**一条规则只讲一件事。** 讲不完就拆成两条，不许膨胀。

## 七、开关策略

| 类型 | constant | 关键词 | 用在哪 |
|---|---|---|---|
| 常驻 | true | 无 | A 核心准则、B 的「武道现状」、L 叶调度、M 变量层 |
| 关键词 | false | 2~4 个 | 其余全部 |
| 关闭待用 | false | 占位词 | 写好了暂不给玩家看的 |

除 A、L、M，任何条目都不许 constant。例外写进该条目的 `注`。

---

## 八、关键词规范

**必须是专名 / 营生词 / 地名，不许用泛化词。**

| 好 | 坏 |
|---|---|
| 真武、紫霄宫、母亲闺名 | 门派、弟子、师父 |
| 观潮、裁云、见山 | 境界、突破 |
| 心法名、招式名 | 心法、武学、功法 |
| 绰号、地名 | 高手、江湖 |

每条 2~4 个，第一项固定是本条目的规范名。

## 十二、Token 控制与按需注入工程定案（2026-11-12）

> 面向 **1M 上下文 / 200k 有效注意力区间** 模型优化：将常驻与当轮注入稳压在 2 万字以内，把 200k 注意力黄金区留给正文长线记忆与人物情感戏。

1. **静态死表移出世界书与 MVU**：`data/*.json`（境界、心法、任务、物价、地标坐标、别名字典等）放进静态只读脚本，专供前端界面与数值脚本查表，**0 Prompt Token 消耗**。
2. **「零文字 `@@generate_before` 叶调度」+ 全员禁递归**：世界书除核心常驻规则外全部设 `constant: false` 并开启 `prevent_recursion` + `exclude_recursion`（PE）；由总控叶调度读取 `stat_data` 后用 `activewi` 精准点亮当轮所需条目（区域只亮 1 州、境界只亮 1 档、规则仅按背包/当前需求激活）。
3. **人物按在场与阶段切片 + 离场防失忆投影**：
   - 仅激活「在场且存活」角色的调色盘与势力详情，角色条目内按好感/情谊阶段 `if/else if` 分支注入当前 1 档；
   - 变量副本对离场/已死 NPC 缩成简表（真实存档不删），但**简表必留 `关系` + `关键备忘（1 句话）`**，且本轮用户输入点名某离场故人时**提及即唤醒**其档案，防长线忘人。
4. **正则 `promptOnly` 清理历史 `<UpdateVariable>`**：发送请求时自动剥离历史楼层的变量更新补丁块（当前最新累加状态已由 `<status_current_variable>` 兜底），防止旧补丁堆积稀释注意力或引起幻觉回退；同时核心常驻规则严格卡在 ≤ 22,000 字红线内。
